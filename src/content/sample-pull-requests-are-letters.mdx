---
title: Pull Requests Are Letters
date: 2025-04-02
lede: Write the description for the person who opens it in two years, because that person is probably you.
---

A pull request has two audiences. The reviewer, who reads it today, and whoever runs `git blame` on it in two years. We write for the first and forget the second.

The second one matters more. The reviewer can ask you questions. The person in two years cannot, and they are usually trying to fix something at a bad time.

> The diff shows what changed. Only the description can say why.

### What goes in the letter

The problem, in one sentence. The approach, in one or two. Anything you tried that did not work, because that is the first thing the next person will try. And a line about what you did not do, so nobody assumes it was forgotten.

That is it. Four short paragraphs. It takes five minutes and I have never regretted writing one.

### What does not

A list of files changed. The diff already has that. A summary generated by a tool that has not read the ticket. Anything that would make the two-years-later reader trust the description less than the code.
